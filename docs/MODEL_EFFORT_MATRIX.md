# Efficient Codex model and reasoning selection

Select only models and levels **actually shown** by the user's Codex interface. Defaults: **Low** for safe discovery/docs, **Medium** for most implementation, **High** only for narrow unresolved architecture/security/credit-integrity failures. Avoid Max/Extra High for routine work. Larger models can use more allowance; the exact subscription usage depends on plan.

| Phase | Purpose | Recommended effort | Suggested model family when shown |
|---|---|---|---|
| 00 | Isolate and bootstrap Git, update handoff | **Low** | Efficient Codex model / GPT-6 Luna |
| 01 | Inspect visual references and inventory Studio | **Medium** | Coding model; visual-capable GPT-6.1 Terra if appropriate |
| 02 | Architecture, data and API contracts | **Medium** (High for architectural dispute) | GPT-6.2 Sol; Astra selectively |
| 03 | Fresh Next.js app, Neon, auth and storage | **Medium** | GPT-6.2 Sol |
| 04 | Marketing brand, localization and assets | **Medium** | GPT-6.2 Sol |
| 05 | Studio UI and tool workflows | **Medium** | GPT-6.2 Sol |
| 06 | AI jobs, providers, image/video integration | **Medium**, High for hard async failures | GPT-6.2 Sol; Astra selectively |
| 07 | Credits, subscriptions, payment | **Medium**, High for ledger/data-integrity verification | GPT-6.2 Sol; Astra selectively |
| 08 | Private/public library, rights, consent | **Medium** | GPT-6.2 Sol |
| 09 | Payload CMS cloud, editorial approvals | **Medium** | GPT-6.2 Sol |
| 10 | Manual social publishing and future adapter | **Low** (Medium for schema/hooks) | Efficient model / Luna or Sol |
| 11 | Prana: Consultation, Tips, Film | **Medium** | GPT-6.2 Sol |
| 12 | Contextual waiting, Home Experience, budget | **Medium** | GPT-6.2 Sol |
| 13 | Security, accessibility, full tests | **Medium**, High for complex security problems | GPT-6.2 Sol; Astra selectively |
| 14 | Staging QA, handoff and release gates | **Medium** | GPT-6.2 Sol |

Daily efficiency: 1 small phase/increment per prompt; verify evidence before code; read only relevant files; update Markdown handoff; never repeatedly re-audit; don't run full test suite for every text edit; switch to High only after presenting a concrete blocking issue. This is guidance, not a guaranteed credit saving.
