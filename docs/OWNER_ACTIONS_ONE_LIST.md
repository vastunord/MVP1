# Commercial release checklist

The protected test environment has passed email registration and verification, first sign-in, private project creation, image upload, retrieval and deletion. Google, GitHub and Apple account login and newsletter subscription are separate features. The following items remain before public commercial use.

1. **Hosting and Production isolation.** Choose an eligible business plan for the Vastu Nord project. Replace the unverified Production database setting with its restricted Frankfurt pool, verify private Blob access, rehearse recovery and test signing in, deleting an account and restoring service. [Vercel Hobby terms](https://vercel.com/docs/plans/hobby)
2. **Rendering and newsletter.** Refresh the protected Development migrator credential, and supply a separate migration-only direct credential for the Preview branch. Run the two reviewed Prisma migrations, confirm checksums and grant the application only the required DML. Test one private MNML job from upload through deletion and one controlled Resend opt-in, confirmation and unsubscribe. GroqAPI and MNMLAPI already exist. Provider spending controls are managed in those accounts.
3. **Social sign-in.** Register Vastu Nord Google, GitHub and Apple web clients. Register each exact HTTPS test origin followed by `/api/auth/callback/google`, `/api/auth/callback/github` or `/api/auth/callback/apple`. Configure the corresponding client ID, client secret and enable flag. Apple requires a Services ID, a signed expiring client secret and a verified web domain. Verify consent, callback, session and private workspace for each provider. [Environment inventory](ENVIRONMENT_VARIABLE_INVENTORY.md)
4. **Content and public rights.** Approve the operator/contact details, terms, privacy, retention, editorial review and commercial rights for images/fonts. Sign off both languages and the Figma comparison. Publish an embeddable film on the [Vastu Nord channel](https://www.youtube.com/@VastuNord). The gallery currently serves approved demonstration images.
5. **Publishing, discovery and operations.** Activate the separate editorial CMS if staff publishing is needed. Rehearse consent withdrawal and support escalation. Verify authenticated customer journeys, alerts, backup recovery, accessibility, critical routes and the public sitemap on the business host before opening registration and indexing. Billing and external social publishing require separate releases.
