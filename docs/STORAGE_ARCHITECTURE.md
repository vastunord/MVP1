## Upload and access boundary

The shared Studio upload component associates an image with an owned project, previews local images, lists saved images and allows selection and deletion. The authenticated project-assets route validates the request origin, verified session, project access, MIME type, actual size and decoded image contents before accepting JPEG, PNG or WebP. The maximum is 4 MiB and the decoder rejects images over 16 million pixels or multiple pages. Server-side upload is used to fit the Vercel Functions request limit; larger direct uploads require a later reviewed design. `sharp` checks image structure but is not malware scanning or moderation.

The server stores a randomly named object with private access and creates workspace/owner/project metadata in Neon. No store credential goes to the browser. The download route verifies the owner and workspace before issuing a one-minute signed private URL; any existing signed URL may remain usable until expiry. Deletion first retires the record and then removes the object. A deletion failure can be retried by the owner. Public gallery and channel-specific consents remain separate; no automatic publication occurs.

If a normal upload operation fails, the service quarantines the record, removes the object and discards the pending record when cleanup succeeds. If cleanup fails, a quarantined record remains hidden for reconciliation. The guarded `/api/internal/media-reconcile` endpoint accepts only explicit Development/Preview configuration, a separate bearer secret, and the verified branch/store pair. It handles at most 20 stale pending/quarantined records and scans at most 20 private objects per invocation, with a cursor for subsequent pages; only old generated keys lacking an active asset or linked to a deleted asset are removed. Local synthetic fixtures test target pairing, production denial, age/key filtering, limits and retries; a synthetic Development Blob confirmed repeated deletion succeeds. Separate environment-scoped secrets and flags are configured, but **no schedule is active and the endpoint has not been tested against live stale records**. Standard Vercel Cron is Production-only; Preview-capable Vercel Schedules/queue integration requires a verified Preview deployment. Do not claim complete orphan-free cleanup. Production enablement requires a reviewed schedule, metadata removal policy, malware/content scanning or quarantine, per-user quantity/rate limits, retention/deletion and the restricted database role.
